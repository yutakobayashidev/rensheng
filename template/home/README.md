# Home

Housing arrangements and practical information needed to live in, maintain, or leave a home.

## Files

| File | Contents | Suggested headings |
| --- | --- | --- |
| `overview.md` | Current housing and active issues | Current home / Active issues / Important references |
| `housing.md` | Living arrangement, contract context, and practical contacts | Current arrangement / Contract / Contacts / Open loops / Sources |
| `utilities.md` | Service providers and setup, move, or cancellation procedures | Services / Procedures / Contacts / References |
| `equipment/item.md` | Equipment with useful maintenance or warranty information | Item / Location / Maintenance / Warranty / References |
| `repairs/YYYY-MM-DD-item.md` | A particular issue and its resolution | Problem / Current status / Actions taken / Next step / Sources |

An inventory of every possession is unnecessary. Create equipment and repair pages only when they will be useful to refer to later.

## Example: a repair page

Fictional example, not information about the repository owner:

```markdown
# 2026-01-15 — Desk lamp

## Problem

- The switch does not reliably turn the lamp on. Source: the user's report.

## Current status

Verified as of: 2026-01-15. Waiting for a response from the seller. [S1]

## Actions taken

- 2026-01-15: sent a warranty inquiry. [S1]

## Next step

- Follow-up is tracked in the execution app; include its task reference.

## Sources

- S1: reference to the warranty inquiry.
- Equipment details: reference to the related equipment page, if one exists.
```

## Updating

Follow [the shared update rules](../AGENTS.md). Payment amounts and terms belong in [money/](../money/README.md); relationship context belongs in [people/](../people/README.md). Link those details instead of maintaining multiple copies. Keep practical procedures here and general home-maintenance knowledge in the Garden.
