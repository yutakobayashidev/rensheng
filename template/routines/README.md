# Routines

Practical procedures the user uses in daily life. A routine page explains how to do something and how to resume it with less effort.

## Files

Use one file per procedure, such as `morning.md`, `departure.md`, or `weekly-admin.md`. An overview is optional and useful only when there are enough routines to need an entrypoint.

Suggested headings: `When`, `Steps`, `Minimum version`, `Exceptions`, `Recording`, and `Notes`. Omit sections that do not help.

## Example: morning.md

Fictional example; these are not routines assigned to the repository owner.

```markdown
# Morning preparation

## When

After waking up. No fixed start time.

## Steps

1. Drink water.
2. Open the curtains.
3. On days out, check the bag and keys.

## Minimum version

Check the bag and keys before leaving. This shorter version was chosen by the user.

## Exceptions

When travelling, use the departure checklist instead.

## Recording

Reference to the routine in the execution app, if one is used.

## Notes

The user's own adjustments or reasons for changing the procedure.
```

## Updating

Follow [the shared update rules](../AGENTS.md). When an execution app manages the routine, it owns recurrence settings, daily occurrences, and execution records; this page is a reference for the procedure and its background. Do not manually maintain the same schedule in both places.

A page may also describe a procedure that has never been registered in an app. Do not automatically turn every procedure into a scheduled task. Optional measurement or medication steps link to their recording app; completing a checklist is not evidence that a measurement or intake was recorded.
