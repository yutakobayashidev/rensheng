# Profile

Stable Personal Context the user wants humans and Agents to know. The five existing files are enough to start; there is no need to fill every suggested heading.

## Files

| File | Contents | Suggested headings |
| --- | --- | --- |
| `overview.md` | A short introduction and pointers to focused pages | Overview / Important context / References |
| `background.md` | Significant personal, educational, and work history | Background / Milestones / References |
| `communication.md` | How the user wants to communicate | Language and tone / Preferred interaction / Avoid |
| `work-patterns.md` | Conditions and practices that help with work | Conditions that help / Friction / Working practices |
| `preferences.md` | Explicit preferences and constraints | Explicit preferences / Constraints / Avoid |

Current roles, applications, care, and contracts belong in their Domains. Profile pages can summarize and link to them without reproducing their details.

## Example: overview.md

Fictional example, not information about the repository owner:

```markdown
# Profile

## Overview

- Preferred name: Morgan. Source: the user's introduction, 2026-01-15.
- Background: previously worked in event operations; see background.md.

## Important context

- When discussing work, consult career/overview.md for current responsibilities.

## References

- communication.md: explicit interaction preferences.
- preferences.md: the user's stated preferences and constraints.
```

## Updating

Follow [the shared update rules](../AGENTS.md). Preserve the user's statements and their scope. A changed preference can replace an outdated current summary while retaining useful context about when it changed. Do not rewrite identity from observed behavior or treat a single difficult day as a stable work pattern.
